# Internationalization

The web app supports `vi` and `en` through `next-intl`. All user-visible UI
text must be defined in both `messages/vi.json` and `messages/en.json`.

## Rules

- Client components use `useTranslations()` or `useTranslations(namespace)`.
- Server components use `getTranslations()` from `next-intl/server`.
- Do not put translated strings directly in JSX, attributes, toast/error
  messages, empty states, options, or `L ? "..." : "..."` branches.
- Do not force `vi-VN` when formatting a user-visible date or number. Use the
  active locale instead.
- Route handlers and outbound notifications must resolve the recipient/request
  locale before composing user-visible text. Keep transport-only status codes
  and database values untranslated.
- Product names, database seed data, imported catalog metadata, identifiers,
  and source-code comments are not UI-copy translations.

## Change checklist

1. Add the same key and interpolation variables to both message files.
2. Render it with `t("namespace.key")`; never select a language manually.
3. Test the affected screen in both `vi` and `en`.
4. Run `bun run lint` and `bunx tsc --noEmit` before merging.

## Review check

Before approving UI work, search the affected `src/app` and `src/components`
files for Vietnamese diacritics. Any result must either be a translation key,
domain data, or have an explicit reason documented in the review.
