## Repo này chỉ còn giao diện web

- Backend (API `src/app/api`, database, `drizzle/`, workers, `ops/`) nằm ở repo riêng
  tư `luma-soft/luma-pos-backend`, gắn vào đây làm submodule `vendor/backend`
  (`git submodule update --init`). Sửa schema, migration, API, action hay data
  loader thì sửa ở backend.
- Các tệp có dòng đầu `Generated by luma-pos-backend scripts/web-rpc/generate.ts`
  (trong `src/lib/actions`, `src/lib/data`, …) là proxy gọi backend; không sửa
  tay. Khi backend thêm/đổi module trong `src/lib/web-rpc/modules.json`, chạy
  `bun run web-rpc:generate` trong `luma-pos-backend` rồi commit proxy ở đây.
- Code không chạm DB của backend (types, schema zod, định dạng…) được import qua
  `@/…` (tsconfig rơi về `vendor/backend/src`). `bun run check:backend-boundary`
  phải không báo lỗi: web không được kéo code DB vào bundle.
- Chạy local: backend `bun run dev` (cổng 3201; 3001 là backend thật của store Mac) trong `luma-pos-backend`, web
  `bun run dev` (cổng 3000) ở đây; hai bên dùng chung `LUMAPOS_WEB_PROXY_SECRET`
  trong `.env.local`.

## Database migrations (làm trong luma-pos-backend)

- Dùng credentials của `DATABASE_URL` hiện có; không hỏi lại người dùng về biến kết nối migration riêng. Nếu URL là Supabase pooler cổng 6543, thử endpoint session cùng host/credentials ở cổng 5432 và truyền qua `MIGRATION_DATABASE_URL` cho riêng tiến trình runner. Giữ nguyên kiểm tra session/advisory lock; không in credentials.
- Khi thay đổi schema hoặc thêm/sửa file trong `drizzle/`, phải tự động chạy `bun run src/db/apply-migrations.ts` trên database được cấu hình sau khi kiểm tra migration. Không được chỉ tạo file migration rồi bàn giao.
- Sau khi chạy, phải xác minh không còn migration pending và truy vấn được các bảng/cột vừa thay đổi trước khi báo hoàn tất.
- Dùng migration runner có tracking `_migrations`; không dùng `db:push` chỉ để apply một migration đã tồn tại.

## Git workflow preference

- Mặc định làm việc trực tiếp trên branch `main`; không tự tạo branch hoặc mở PR.
- Sau khi hoàn tất một task thay đổi code, mặc định commit các thay đổi thuộc task và push trực tiếp lên `origin/main`, trừ khi người dùng nói rõ không push.
- Không chờ người dùng nhắc lại việc commit/push; luôn kiểm tra `git status`, không đưa file tạm hoặc thay đổi ngoài phạm vi task vào commit.

## GitHub Actions workflows

- Chỉ được giữ workflow `.github/workflows/keep-supabase-alive.yml` để giữ Supabase hoạt động.
- Tuyệt đối không tự ý tạo mới, khôi phục hoặc bổ sung GitHub Actions workflow khác khi chưa được người dùng phê duyệt rõ ràng, kể cả CI, lint, typecheck, build, test hay parity checks.
- Khi cần kiểm tra code, ưu tiên chạy thủ công trong môi trường phát triển; không thiết lập workflow tự động trên GitHub.
- Không sửa/xóa workflow keep-alive Supabase khi không có yêu cầu cụ thể từ người dùng.

## Picker và dropdown hiển thị cho người dùng

- Không dùng `<select>` hoặc `<datalist>` native làm bề mặt tương tác hiển thị
  cho picker, bộ lọc hay menu của Luma web. Popup native phụ thuộc hệ điều hành
  và không khớp design system Luma.
- Mặc định phải dùng picker Luma tùy biến: trigger được style, popover/listbox
  có kiểm soát (hoặc responsive sheet đã được duyệt), đầy đủ trạng thái đang
  chọn, hover/focus, điều hướng bàn phím, đóng khi click ra ngoài và nhãn tiếng
  Việt nhất quán.
- Chỉ được dùng control native khi người dùng yêu cầu rõ UI native hoặc làm
  fallback form/accessibility không hiển thị. Không được dùng native chỉ vì
  triển khai nhanh hơn.
- Khi chuyển flow từ mobile sang web, phải đồng bộ cả business logic lẫn interaction
  model; không được thay Luma picker trên mobile bằng dropdown native trên web.
- Trước khi chốt UI picker, bắt buộc kiểm tra trạng thái đã mở trên browser mục
  tiêu. Chỉ kiểm tra trigger khi đang đóng là chưa đủ.

## Khoảng cách màn mobile (khớp iOS)

- Màn web dưới 1024px dùng bộ biến khoảng cách trong `src/app/globals.css`,
  khớp `LumaLayoutMetrics` của app iOS: `ios-inset` (16, lề ngang/nội dung),
  `ios-section` (16, giữa các khối), `ios-search` (10, ô tìm ↔ nút lọc/+),
  `ios-row` (13, đệm dọc dòng list), `ios-field` (8), `ios-label` (6),
  `ios-control` (52, nút chính), `ios-compact` (44).
- Dùng lớp Tailwind tương ứng (`px-ios-inset`, `gap-ios-search`, `py-ios-row`,
  `space-y-ios-section`, `h-ios-compact`…) thay cho số cứng; khi iOS đổi
  metric thì sửa một chỗ ở `globals.css`.
